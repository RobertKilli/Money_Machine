# Evidence review queue snapshot provenance manifest codec

This server-only, in-memory codec gives the existing syntactic provenance manifest a canonical v1 wire representation. It does not create manifests from composition and does not change the manifest parser, snapshot codec, scope identity, or manifest-binding contracts.

The exact profile is `event-intelligence-evidence-review-queue-snapshot-provenance-manifest-canonical-json/v1`. The wire envelope has exactly two fields: `manifestCodecProfile` and `manifest`. The profile is included in the wire bytes. The SHA-256 digest is returned separately and never included in its own preimage. The snapshot digest inside the manifest identifies canonical snapshot-envelope bytes; the codec digest identifies these manifest-wire bytes. They are distinct values with distinct inputs.

Canonical JSON uses recursively lexically sorted object keys compared by UTF-16 code units. Arrays retain their order, except the top-level manifest member inventory: encoding sorts a copy by the explicit family order below, then by the canonical JSON representation of the complete validated family reference, also compared by UTF-16 code units. It regenerates dense zero-based ordinals. References and their nested arrays are preserved. It neither mutates the caller’s arrays nor removes duplicates. The order is an inventory normalization only; it is not derivation order, source priority, or authority.

The family order is the order already declared by the family contract: `SEC_EVENT_DOCUMENT`, `ISSUER_EVIDENCE`, `ASSET_MAPPING_REVISION`, `DISCOVERY_SOURCE_RECORD`, `CORRECTION_LINEAGE`, `DERIVED_COMPOSITION`, `DERIVED_QUEUE_SET`, `DERIVED_VIEW_MODEL`. The tie-break key includes every validated reference field, including version, nested parent keys, ordered arrays, and correction `evaluationAsOf`. Nested array order remains significant. Canonical strings use JSON string escaping without Unicode normalization; accepted family values are ASCII under the reused family parser. Ordinals are safe nonnegative integers with negative zero rejected. There is no whitespace, BOM, or trailing newline.

The wire limit is 768 KiB (786,432 bytes), applied to UTF-8 bytes and including the complete envelope. A conservative maximum-material estimate uses the largest current family shape, `CORRECTION_LINEAGE`: up to 64 ASCII SHA-256 values in its ordered array (at most 4,289 JSON bytes including quotes and separators), its remaining fixed ASCII fields and keys, and a member’s repeated 64-character snapshot digest, 71-character scope identity, ordinal and keys. Budgeting 5,500 bytes per member covers that shape and its JSON punctuation; 128 members therefore fit within 704,000 bytes. Allowing a further 4,096 bytes for root and envelope material yields 708,096 bytes, below the configured limit. Other family shapes are smaller under their current parser constraints. The bound is a rejection limit, not a streaming or allocation sandbox.

Encoding first invokes the existing strict manifest parser, then sorts an isolated validated inventory, serializes and hashes its UTF-8 bytes. The returned byte array is a mutable copy; its digest describes the bytes at encode time and must be recomputed if the caller changes that array.

Decoding accepts a `Uint8Array` (including `Buffer` and views) and a separate expected lowercase SHA-256. It checks byte type/length, rejects shared backing buffers, copies exactly the view, validates the expected digest and compares it with SHA-256 of the copied bytes, rejects a UTF-8 BOM, decodes fatal UTF-8, parses JSON, validates the exact envelope and existing manifest schema, canonicalizes a copy, and requires byte-for-byte equality. Noncanonical bytes are rejected rather than repaired. Duplicate JSON keys survive JSON parsing only as the last value and therefore fail canonical readback. The parser enforces existing exact family shapes, bindings, duplicate-reference rules, and structural bounds. This codec does not bind snapshot bytes, scope material, or correction cutoffs; those checks remain with the existing local binding verifier.

The digest detects changes only relative to a separately retained expected digest. A caller able to replace both manifest and expected digest can submit another valid inventory. Neither canonicalization nor digest/readback authenticates that expectation, the producer, parents, or content.

Successful results are explicitly non-authoritative. Decoded envelopes and manifests are isolated and deeply frozen. Encode bytes are intentionally caller-owned and mutable. Codec success does not establish parent existence, correct source classification, authentic composition, provenance completeness, origin independence, policy approval/access, queue membership, or event/signal/trading authority. The manifest remains a snapshot-level reference inventory, not a row-level derivation graph. No resolver, seal/signature, persistence, storage read, current-selection, production wiring, or completeness status is added here.
