# SEC EDGAR event-source provenance runtime

This first runtime foundation persists only synthetic, non-authoritative fixture material. Production remains `BLOCKED_BACKEND_UNAPPROVED`; it does not authorize live SEC acquisition, raw or normalized content use, authority persistence, retention, redistribution, or commercial use.

## Authorities

Migration `20261002090638_sec_edgar_event_source_provenance.sql` adds eleven append-only tables: `sec_event_source_profiles`, `sec_event_filing_identities`, `sec_event_acquisition_requests`, `sec_event_acquisition_attempts`, `sec_event_content_blobs`, `sec_event_document_artifacts`, `sec_event_filing_packages`, `sec_event_package_document_members`, `sec_event_acquisition_receipts`, `sec_event_source_lineages`, and `sec_event_source_lineage_members`. Filing identities carry the nullable amendment-parent relation. Blobs are deduplicated by lowercase SHA-256 and byte length. A blob identifies bytes; an artifact identifies a locator, role, type and filing scope. Package membership seals a filing's ordered documents; event-source lineage independently seals selected references to those package members.

## Bytes and readback

The adapter accepts fixture-provided entity-body octets. It does not claim these are observed SEC HTTP responses. The runtime hashes exact bytes incrementally in the application, stores the logical sequence in PostgreSQL `bytea`, selects one blob at a time, compares byte count and every octet, and recomputes SHA-256 before commit. It has no `pgcrypto` dependency. A later SELECT returns the logical `bytea` value; TOAST's physical compression/out-of-line representation is not part of byte identity. Receipt, `stored_at`, and readback time do not change blob, artifact, package, or lineage identity.

## Sealing, transactions, and limits

One UoW uses `READ COMMITTED`, one PostgreSQL transaction, and this order: source profile, filing identity/amendment parent, request/attempt, blobs sorted by key, artifacts sorted by ID, package, package members, receipt, lineage, lineage members. An amendment must reference an already persisted parent identity; the UoW never fabricates one from an accession string. Parent FK scope, one-child amendment branch, and parent/package filing-date chronology are enforced by the relation and deferred invariant trigger. Acquisition chronology is also checked at commit: request time must not follow attempt start, and receipt retrieval must not precede request or attempt time. Effective availability may precede retrieval because it represents when the filing became available, not when this attempt observed it. Request authoritative reread acquires `FOR UPDATE` before attempt ordinal allocation, preventing a READ COMMITTED race on a later receipt for an existing request. Unique constraints arbitrate writes; `ON CONFLICT DO NOTHING` is followed by authoritative reread; the UoW has no hidden retry. Deferred constraint triggers validate package and lineage member sets at commit. The database checks structural digest shape, blob address, and byte length, but does not compute SHA-256. Application readback recomputes the digest over returned logical `bytea`. Any thrown database error, cancellation, timeout, or integrity mismatch rolls the complete transaction back. All authoritative queries are key/member-scope bounded; the former eleven global table-count scans are removed. Package seal checks the copied document type against its immutable artifact. Lineage seal checks root and the ordered amendment chain against actual filing authorities and requires selected members to belong to that context, while permitting proper subsets and cross-revision selections. Concurrent identical writers converge through uniqueness plus reread; conflicting material fails rather than blending parent/member sets.

An amendment cycle is `UNREACHABLE_BY_AUTHENTICATED_CONSTRUCTION` through this adapter/UoW: the authentic fixture chain has an original 8-K parent, and the UoW requires that parent to be committed already. An immediate FK alone does not prove database unreachability: a multi-row INSERT can create two mutually referencing amendments. A direct SQL regression proves both rows INSERT successfully and the recursive deferred trigger rejects COMMIT with 23514 `SEC_EVENT_AMENDMENT_CYCLE`, without bypassing constraints. Package INSERT also queues amendment chronology validation, including when identities were committed earlier. Validators serialize on the immutable amendment root using `FOR NO KEY UPDATE` (compatible with FK key-share locks) and check both parent and child package arrivals.

Local v1 safety limits are 8 MiB per document, 64 MiB across the package (including its index), 32 non-index package documents, 15 seconds per document, 8 minutes acquisition per package, 2 minutes per database transaction, and a 96 MiB active package-worker payload budget. These are application safety limits, not SEC or PostgreSQL limits. Before allocating entity buffers, adapter admission checks `2 * total body bytes + 4 * largest body bytes`: ingress and the private immutable snapshots, plus bounded per-document readback/driver work. Consequently a package below 64 MiB may still be rejected by the independent memory gate; for example, six 8 MiB bodies reserve 128 MiB and fail before UoW. Four 8 MiB bodies reserve exactly 96 MiB and pass the numeric bounds gate. This is deterministic byte-payload accounting, not a measured cap on V8 heap or process RSS; object/string/runtime overhead is an operational provisioning requirement before production approval.

The fixture adapter retains private immutable entity snapshots; the production batch factory accepts only those same-runtime adapter objects, rejecting arbitrary material, copies and proxies before accessing properties. Unit/integration compiler access to the private constructor is separate from public trust issuance. The optional worker admission port receives the computed payload budget before byte allocation and returns a lease released in application `finally` on success, parser/admission failure, UoW failure, cancellation and rollback. This is an admission/accounting boundary, not a process memory allocator. The sealed batch material and document authority reuse the same private body snapshot and return isolated byte copies. Receipt metadata is separately snapshotted and frozen. UoW holds one expected body copy for comparison and reads one blob at a time. postgres.js encodes an individual `bytea` parameter as hex and decodes an individual returned row; this bounded driver representation does not normalize the logical bytes. There is no package-concatenation or application base64 encoding, and no claim of PostgreSQL-driver streaming. The synthetic adapter has no acquisition transport; deadline/admission ports prove timeout/cancellation before transaction without sleeps. PostgreSQL 17 `transaction_timeout=120s` caps the complete UoW, with a local `statement_timeout=120s`; infrastructure errors propagate without retry. See [PostgreSQL 17 client connection defaults](https://www.postgresql.org/docs/17/runtime-config-client.html), checked 2026-10-02.

## Access and deletion

All eleven public tables have RLS enabled, no policies, and no privileges for `PUBLIC`, `anon`, `authenticated`, or `service_role`; the runtime connects through its narrow server-side PostgreSQL UoW. Invariant functions use `SECURITY INVOKER`, fixed `search_path`, and revoked execute privileges. Immutable triggers reject ordinary updates/deletes. Retention and deletion remain `NOT_APPROVED`. No correction, tombstone, legal-hold, deletion, or backup-erasure workflow is implemented; those require separate authority and policy. Do not infer physical erasure from deleting a future live row while backups/PITR copies remain.

## Receipt variation

The merged provenance contract defines event lineage over the source profile, ordered package-document member references and amendment context. Receipt ID, retrieval time, and effective availability are excluded. Repeating the same package therefore creates a new attempt and receipt but keeps the same source profile, filing identity, blobs, artifacts, package, package members and lineage. This encodes stable evidence-set identity; receipts remain independently queryable observation authorities.

## Document artifact authority conflicts

Reusing an artifact ID after changing bytes/blob, locator, role, profile or filing scope is `UNREACHABLE_BY_AUTHENTICATED_CONSTRUCTION`: the runtime derives the artifact ID from the complete document fingerprint, including filing identity; filing identity binds profile ID and fingerprint. The currently approved synthetic runtime also rejects an alternative source-profile ID. Changing role may require a compatible document type and another primary document; changing filing scope requires a locator in the new accession's canonical archive path. These are coordinated scope changes, not claims that only one SQL column changes.

The UoW retains a separate persistence defense. Its private `persistDocumentArtifact` operation performs `ON CONFLICT DO NOTHING`, then selects every document identity column plus the profile binding joined from the immutable filing parent. A mismatch throws `SEC_EVENT_DOCUMENT_ARTIFACT_AUTHORITY_CONFLICT`; it is an application error, with no SQLSTATE. The transaction propagates the same Error instance and rolls back, preserving the previously committed baseline artifact.

The five conflict integration cases access that private operation through the integration test loader only. The loader appends an export to its test module copy; production exports no private artifact writer or raw-material constructor. The batch guard remains in place; construction requires an authenticated adapter result. Synthetic canary batches and deliberate invalid-material cases now use a private-constructor compiler seam in unit/integration tests, never a production trust issuer. Tests run the authentic UoW in a real transaction, use its existing phase observer at `BLOB_VERIFIED`, and pass a deliberately reused artifact ID only to the private persistence record. Alternative blob/profile/filing parents already exist, the locator is canonical and otherwise unused, and both roles are allowed. The insert must complete with zero returned rows, followed by one authoritative reread and the sanitized conflict. A separate authenticated canary authority-set written in the same transaction must disappear on rollback; all eleven table counts and the complete baseline artifact row are compared from a fresh connection. No immutable trigger, FK, CHECK or UNIQUE constraint is disabled in these five cases.

## Finalization evidence

The consolidated [A–G verification report](SEC_EDGAR_EVENT_SOURCE_PROVENANCE_RUNTIME_VERIFICATION.md) records the actual enforcement layer, SQLSTATE or application code, exact eleven-table count maps, controlled concurrency results, and catalog/advisor evidence from two complete runs without reset. Application results explicitly carry `SYNTHETIC_NON_AUTHORITATIVE` and `eventAuthorityEligible=false`; they carry no bytes, event authority or downstream runtime trust.

The final catalog check compares every physical column/type/nullability and ordered FK to the migration, and all required columns/PK/UNIQUE tuples to the merged provenance descriptor. It found three missing descriptor keys, now added without changing existing constraints: `sec_event_filing_identity_material_scope_key`, `sec_event_attempt_identity_fingerprint_key`, and `sec_event_artifact_role_sequence_key`. They expose the explicitly specified composite identity tuples; no existing migration was edited and no duplicate index definition is introduced.

Rollback observers now distinguish request, attempt, blob verification, artifacts, package parent, package members, receipt, lineage parent, lineage members and pre-commit. Observers cannot create runtime trust. The normal UoW also rejects copied trusted batches before opening a transaction. SQLSTATE propagation tests deliberately inject `57014`, `40001` and `40P01` in PostgreSQL: they prove unchanged errors and full rollback, without claiming to reproduce a real elapsed timeout, serialization anomaly or deadlock schedule.

Concurrent conflicting authentic batches share a deterministic request key while their package fingerprint differs. The losing writer fails at request authoritative reread with `SEC_EVENT_ACQUISITION_REQUEST_AUTHORITY_CONFLICT`, before blob/artifact writes; the test separately verifies the winning package and absence of the loser's unique blob. Five integration-only artifact-record conflict cases retain the later defense at artifact reread. These are distinct boundaries.

The private artifact integration loader is defined only in `vitest.integration.config.ts`; the constructor test compiler is configured only in the two Vitest configs, and its declaration is under `tests/helpers/`. Production imports cannot resolve `test-only:sec-artifact-uow`; production source exports no private artifact writer, fixture trust mutator or bypass flag. The detached application build is checked for absence of the virtual module and injected sentinel strings. Privileged corruption simulations in the already approved A–F tests are transaction-local and rolled back; they do not represent an authorized mutation path. The five artifact-record seam tests and G require no constraint bypass.

## Scope still blocked

This migration does not persist extracted claims, issuer/asset mapping, corroboration eligibility, event authority, signals, or trading data. It adds no live transport, credential resolver, scheduler, Supabase Storage, or provider integration. Production remains `BLOCKED_BACKEND_UNAPPROVED`; live acquisition, raw-byte processing/storage, normalized storage, authority persistence, retention, redistribution and commercial use remain separate approvals. Retention/deletion/backup-erasure workflows are not implemented. This runtime provides synthetic local persistence evidence only.
