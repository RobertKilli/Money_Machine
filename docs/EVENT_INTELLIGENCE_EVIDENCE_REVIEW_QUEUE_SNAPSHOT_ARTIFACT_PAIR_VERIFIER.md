# Evidence review queue snapshot artifact-pair verifier

`verifyEvidenceReviewQueueSnapshotArtifactPair` is a server-only, in-memory composition of the existing manifest codec and snapshot-manifest binding verifier. Its six required positional inputs are snapshot bytes, expected snapshot SHA-256, manifest bytes, expected manifest SHA-256, expected scope identity, and expected scope material. No expectation is derived from either artifact or a prior result.

The verifier decodes the manifest bytes against the separately supplied manifest digest first. A codec rejection returns `MANIFEST_CODEC_REJECTED` with only the codec's closed bounded error. Only after that succeeds does it pass the decoded manifest to the existing snapshot-manifest binding verifier with snapshot bytes and the separate snapshot/scope expectations. A parent rejection returns `SNAPSHOT_MANIFEST_BINDING_REJECTED` with the parent verifier's closed bounded error. Thus manifest-codec failures take priority over snapshot, scope, and manifest-to-snapshot binding failures.

Success has status `VERIFIED_LOCAL_ARTIFACT_PAIR_NON_AUTHORITATIVE`. The result carries this verifier's contract version, recomputed snapshot digest, recomputed manifest digest, verified scope identity, the existing verifier's isolated immutable snapshot envelope, and its isolated immutable canonical manifest. It returns no artifact bytes. Caller inputs are not mutated or frozen.

Success means each artifact's bytes matched its separately supplied digest and passed its existing canonical codec; the snapshot scope matched the supplied scope material and identity; the manifest's snapshot digest and scope matched the verified snapshot; and every declared correction evaluation time matched the envelope cutoff. The verifier does not authenticate who supplied any expected value. Replacing a manifest and supplying its new correct digest can still pass when its bindings match; replacing it against an unchanged digest is rejected by the codec.

This result is not an authenticated expectation record or production read authorization. It does not establish authentic producer/composition, parent existence or source classification, provenance completeness, row/candidate derivation, origin independence/corroboration, policy-content integrity, approval/access, or event/signal/trading authority. It adds no trust capabilities, registry, persistence, storage read, current selection, or production wiring.

Production use remains blocked pending an authentic expectation source, approved scope and policy registries/content, producer and provenance contracts, rights approvals, and separate storage/read/current-selection decisions. The existing production config remains blocked, active registries remain empty, approvals remain unapproved, authority upgrades remain unsupported, and signal/trading remain blocked.
