# SEC EDGAR Form 8-K event source qualification

Contract: `sec-edgar-8k-event-source-qualification/v1`. Review control time: 2026-09-30 07:17 UTC. This qualifies a bounded SEC source profile; it does not retrieve filings, parse filing text, issue events, persist data, or enable a scheduler or signal.

## Scope and decision

**PARTIAL.** Scope is public SEC EDGAR registrant submissions for Form `8-K` and `8-K/A`, jurisdiction US, regulator SEC. Form `6-K`, `10-K`, `10-Q`, registration statements, filer submissions/authentication APIs and XBRL facts are separate or unsupported profiles. The submissions API may contain those other forms, but its existence does not extend this source qualification to them.

| Profile | Host/path | Role and limit |
|---|---|---|
| `COMPANY_SUBMISSIONS_JSON` | `data.sec.gov/submissions/CIK{10-digit-zero-padded-CIK}.json` | Filing metadata/history by filer CIK; reconcile by accession and form, not company ticker/name. |
| `SUBMISSIONS_HISTORY_JSON` | `data.sec.gov/submissions/{filename}` where filename is referenced by that CIK's current submissions record | Referenced history file; keep filename within the same CIK scope. |
| `FILING_INDEX` | `www.sec.gov/Archives/edgar/data/{unpadded-CIK}/{accession-without-dashes}/{accession-dashed}-index.htm` | Filing-scoped index/header and document list; locate primary document and exhibits. |
| `PRIMARY_DOCUMENT` | Same accession directory plus the index-listed primary filename | Source document locator, distinct from filing identity. |
| `EXHIBIT_DOCUMENT` | Same accession directory plus an index-listed exhibit filename | Supporting filing artifact; exact document type/content format is inspected later, not fetched here. |

These are HTTPS GET profiles with no authentication. Redirects may remain only on the original explicitly allowlisted SEC hostname. The RSS query keys are fixed by its profile; arbitrary query parameters are rejected. The supported set is intentionally narrower than the SEC's submissions/XBRL APIs. ## Filing identity and time semantics

The filing key is the tuple `(normalized 10-digit CIK, accession number, form)`. CIK is zero-padded to ten digits in the submissions endpoint; the archive directory uses the CIK without leading zeros. Accession is represented canonically as `##########-YY-######`; its archive directory form removes dashes. SEC documentation notes that the accession's leading CIK can identify the submitting filer agent, so registrant CIK must be separately read from filing metadata/header. Ticker and name are lookup attributes, not issuer identity. A filename or URL is only a locator.

The archive index binds filing metadata and ordered document entries, including sequence, type and filename. The primary document and each exhibit get separate content fingerprints; filing metadata has a different fingerprint. The same accession discovered in RSS, submissions JSON and archive index reconciles to one filing. Filing acceptance, filing date, report date/period, signing date, event announcement, expected closing, completion and local receipt are distinct timestamps. The submissions JSON exposes fields such as accession number, form, filing date, report date, primary document and acceptance datetime where present. Acceptance time is EDGAR processing time, not the underlying event time. [DOCUMENTED: SEC, “EDGAR Application Programming Interfaces (APIs)”, https://www.sec.gov/search-filings/edgar-application-programming-interfaces; “Webmaster Frequently Asked Questions”, https://www.sec.gov/about/webmaster-frequently-asked-questions; “Accessing EDGAR Data”, https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data; checked 2026-09-30 07:17 UTC.]

Form 8-K is a current report. Item 1.01 concerns entering a material definitive agreement, including agreements subject to conditions; it does not mean an acquisition completed. Item 2.01 concerns a consummated significant acquisition or disposition, but item number alone does not establish crypto-asset identity or every event detail. Other items may be relevant. The filing text and exhibits require later document review; forward-looking statements and expected closing are not completion. Form 8-K/A is a separate amendment filing. Link it to an original only when explicit document/material evidence supports that relation; the form suffix and recency alone do not identify the parent. Preserve original metadata and document fingerprints, append a correction/supersession edge, and never overwrite or newest-win. SEC documents same-business-day post-acceptance corrections in that evening's indexes; later removals may not appear in prior daily/feed/oldload indexes, while full and quarterly indexes are rebuilt weekly. A single response therefore cannot prove complete correction history. [DOCUMENTED: SEC, “Form 8-K”, https://www.sec.gov/divisions/corpfin/forms/8-k.htm; “Compliance and Disclosure Interpretations: Exchange Act Form 8-K”, https://www.sec.gov/files/divisions/corpfin/guidance/8-kinterp.htm; “Accessing EDGAR Data”, https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data; checked 2026-09-30 07:17 UTC.]

## Pagination, history, latency and completeness

The submissions recent record uses parallel filing-field arrays. A future fixture parser must zip values by row index and reject missing fields or unequal array lengths; it must not sort each column independently. JSON/Atom responses must be decoded as UTF-8. Filing document media type and declared character encoding must be validated at acquisition, and unsupported formats fail closed. This slice does not parse a SEC response or establish response-specific charset behavior. [DOCUMENTED: SEC, “EDGAR Application Programming Interfaces (APIs)”, https://www.sec.gov/search-filings/edgar-application-programming-interfaces, checked 2026-09-30 07:17 UTC; UTF-8 and rejection behavior are application policy, not SEC guarantees.]

Company submissions JSON contains at least one year or the latest 1,000 submissions (whichever is more); older filings are referenced by additional historical submission files. The JSON API updates through the day as filings disseminate; the `submissions.zip` snapshot is republished nightly at approximately 3:00 a.m. Eastern. Reconciliation must process recent rows, discover and fetch referenced historical files, and compare nightly bulk snapshots without assuming these mechanisms alone prove complete event coverage.

Latest Filings and RSS can filter by company, CIK, or form. Historical Archives search can be ordered alphabetically and its index may lag one business day. RSS/search is useful for discovery, not completeness. SEC reports typical submissions processing under one second and document availability often within one to three minutes, while warning those delays can increase; they are not end-to-end service guarantees. **UNKNOWN:** exact request pagination/update guarantees for every feed/search profile, source-wide completeness, and a stable content-availability timestamp. ## Fair access and future request-plan boundary

SEC requires an identifying User-Agent with contact details and documents a maximum of 10 requests per second across SEC.gov access. This is the provider-documented ceiling, not a target; production request scheduling/concurrency still requires a reviewed budget. Excessive or unclassified automated access may be rate-limited or blocked. The pure request-plan contract records identity by a non-secret approved reference and requires HTTPS GET, same-host redirects only, a profile-specific content-type allowlist, bounded timeout/body/page/file/attempt counts, application-side deterministic capped backoff for HTTP 429/503, and no raw-body logging. Its example bounds (30-second timeout, 25 MiB response, 100 pages/files, 3 attempts, 1-second base and 8-second retry cap) are proposed application safeguards, not SEC limits. SEC endpoint-specific retry and caching/conditional-request guarantees are **UNKNOWN**; a future client must honor provider cache headers when present and avoid redundant retrieval. No HTTP transport is implemented.
